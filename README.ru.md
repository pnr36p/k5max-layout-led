# K5 Max Layout Indicator

[English](README.md) · [Русский](README.ru.md)

Маленькая трей-программа для Windows: подсвечивает клавиши Keychron K5 Max по-разному для каждой раскладки (US, RU, ...), так что активную раскладку видно прямо на клавиатуре. Один exe на 450 КБ, без рантайма, около 2 МБ памяти и 0% CPU в простое.

Цвета описаны в обычном `config.toml`: какие клавиши каким цветом, отдельно для каждой раскладки. Там же описана и сама клавиатура, поэтому другие RGB-клавиатуры с таким же протоколом прошивки можно поддержать без правок кода, см. [Другие клавиатуры](#другие-клавиатуры).

> Проект не связан с Keychron, SignalRGB и QMK. Используйте на свой риск, включая прошивку.

## Как это работает

Программа общается с клавиатурой по raw HID (usage page `0xFF60`, usage `0x61`) протоколом SignalRGB QMK. Само приложение SignalRGB не нужно, но нужна прошивка, которая этот протокол реализует. Штатная прошивка Keychron его не поддерживает.

Каждые 100 мс программа спрашивает у Windows раскладку окна переднего плана и при смене отправляет клавиатуре новый кадр цветов. Кроме того, она перерисовывает подсветку раз в 30 с и после выхода из сна или гибернации, потому что прошивка сбрасывает буфер LED при suspend. Соединение считается установленным только после ответа клавиатуры на запрос. Любая ошибка ввода-вывода закрывает хэндл и запускает повтор с нарастающей паузой, поэтому клавиатура, пропавшая во время гибернации, не оставит программу в «полуподключённом» состоянии.

## Требования

- Windows 10 или 11
- Keychron K5 Max, ANSI, подключённая **по USB-кабелю** (USB ID `3434:0A50`, 108 LED). Именно её описывает `config.toml` по умолчанию.
- Прошивка с протоколом SignalRGB, см. ниже

Для всего остального нужна другая секция `[device]`, см. [Другие клавиатуры](#другие-клавиатуры). Беспроводные режимы не поддерживаются.

## Шаг 1. Прошивка клавиатуры

Прошивку собирает команда модераторов SignalRGB, она лежит в
[SRGBmods/QMK-Binaries](https://github.com/SRGBmods/QMK-Binaries/tree/main/QMK%2BVIA-Firmware/0.14.29-keychron).
Этот репозиторий её не распространяет.

Я использую файл `keychron_k5_max_ansi_rgb_via.bin` (QMK 0.14.29, протокол SignalRGB 1.0.6, 100 140 байт):

```
SHA-256  991C60E8A75225ED4B99F8081AFC079819DC6CC83A580948879B2E7F59A535F2
```

Файл с таким же именем и размером есть в папке `wireless_playground`. Совпадение только по имени и размеру, поэтому сравните хэш скачанного файла. В папке `2025q3` лежит `keychron_k5_max_ansi_rgb_keychron.bin`, это другая сборка, я её не пробовал. Их ReadMe советует попробовать `bluetooth_playground`, если после прошивки глючит беспроводной режим.

Прошивка по их ReadMe:

1. Установите [QMK Toolbox](https://github.com/qmk/qmk_toolbox/releases).
2. Запустите её от имени администратора и поставьте драйверы через меню Tools (Ctrl+N).
3. Переведите клавиатуру в режим загрузчика, как описано в инструкции Keychron для вашей модели.
4. Выберите `.bin` в QMK Toolbox и прошейте.

Это заменяет заводскую прошивку. Чтобы вернуться, прошейте официальную прошивку для вашей модели с сайта Keychron. На время работы закройте SignalRGB и VIA: они используют тот же HID-интерфейс.

## Шаг 2. Установка программы

Соберите сами (свежий stable Rust с MSVC toolchain, разрабатывалось на 1.99):

```powershell
cargo build --release
```

Exe лежит в `target\release\k5max-indicator.exe`. Положите его в любую папку с правом записи и запустите. При первом запуске рядом создаётся `config.toml`, туда же пишется `k5max-indicator.log`.

Две вспомогательные команды печатают в консоль. У exe нет своей консоли, поэтому добавьте `| more`, чтобы оболочка дождалась вывода:

```powershell
.\k5max-indicator.exe --list | more
.\k5max-indicator.exe --probe | more
```

`--list` показывает подключённые raw HID-интерфейсы с `vid`/`pid` для `config.toml`. Здесь появляется любая QMK-клавиатура с VIA, так что команда подсказывает только USB ID.

`--probe` открывает клавиатуру из `config.toml` и спрашивает у неё параметры протокола. Это настоящая проверка того, что прошивка говорит на нужном протоколе. Для прошивки K5 Max выше:

```
device             3434:0A50
QMK version        [00, 0E, 1D]
protocol version   [01, 00, 06]
total LEDs         108 (matches the 108 keys in config.toml)
firmware type      [02, 00, 06]
```

`00 0E 1D` это QMK 0.14.29.

## Меню в трее

Иконка: зелёная K, когда клавиатура подключена, серая, когда нет.

| Пункт | Действие |
|---|---|
| строка статуса | состояние связи и текущая раскладка |
| Start with Windows | автозапуск для текущего пользователя через ключ реестра `Run` |
| Reload config | перечитывает `config.toml`, при ошибке оставляет прежние цвета |
| Exit | завершает работу, при `restore_on_exit = true` возвращает штатный эффект клавиатуры |

Одновременно работает только один экземпляр.

## Настройка

Вся настройка в [config.toml](config.toml), он подробно прокомментирован. Коротко:

- `[device]` описывает клавиатуру: USB ID и имя каждой клавиши в порядке LED. После изменений перезапустите программу, Reload config эту секцию не применяет.
- `[groups]` даёт имена наборам клавиш.
- `[common]` применяется ко всем раскладкам, `[layouts.<NAME>]` накладывается сверху. В строке можно указать группу или отдельную клавишу, цвет задаётся как `[r, g, b]` или `"#RRGGBB"`. Более поздние строки перекрывают ранние. Клавиши, которых нет в конфиге, остаются тёмными.
- `heartbeat_seconds` задаёт, как часто программа проверяет связь и перерисовывает подсветку. Эффект, выбранный на клавиатуре через Fn, будет перебит не позже чем через это время.
- `log = false` выключает лог-файл. Reload config применяет это сразу и оставляет последнюю строку `log disabled`. По умолчанию лог включён, а если `config.toml` не удалось разобрать, он остаётся включённым, потому что именно тогда он нужен. При 1 МиБ лог переименовывается в `k5max-indicator.log.old`, так что в любом случае он остаётся небольшим.

## Языки

Работает любой язык, не только US и RU. `lang` в секции `[layouts.<NAME>]` это идентификатор языка Windows для раскладки (младшие 16 бит её дескриптора), и у каждой секции свои цвета. Например, добавление немецкой раскладки:

```toml
[layouts.DE]
lang = 0x0407
letters = [255, 200, 0]
numbers = [64, 255, 64]
gaming = [255, 128, 128]
```

затем выберите **Reload config** в меню трея.

| ID | Язык | ID | Язык |
|---|---|---|---|
| `0x0409` | английский (США) | `0x0422` | украинский |
| `0x0809` | английский (Великобритания) | `0x0423` | белорусский |
| `0x0407` | немецкий | `0x0415` | польский |
| `0x040C` | французский | `0x0405` | чешский |
| `0x0410` | итальянский | `0x041F` | турецкий |
| `0x0419` | русский | `0x0411` | японский |

ID задаётся языком, а не конкретной раскладкой: US-International, Dvorak и Colemak все имеют `0x0409` и выглядят одинаково. Чтобы узнать ID любого другого языка, переключитесь на него и найдите строку `input language XXXX` в `k5max-indicator.log`. Для языка без секции берётся `unknown_layout`.

## Другие клавиатуры

Код больше ничего не знает про K5 Max: USB ID и список клавиш лежат в `[device]`. Программа должна работать с любой клавиатурой с подсветкой по клавишам, проводным подключением и прошивкой с протоколом SignalRGB QMK. Проверена только K5 Max ANSI.

1. **Прошейте сборку SignalRGB** для своей модели, см. [Шаг 1](#шаг-1-прошивка-клавиатуры). Модели с белой подсветкой не подходят: у них нет RGB по клавишам.
2. **Найдите USB ID** командой `--list` и впишите в `vid` и `pid`.
3. **Запустите `--probe`**. Он напечатает число LED вашей клавиатуры, запомните его.
4. **Перечислите клавиши в порядке LED.** Откройте `rgb.c` своей модели в [qmk_firmware от Keychron](https://github.com/Keychron/qmk_firmware) (ветка `wireless_playground`, путь `keyboards/keychron/<модель>/<вариант>/rgb/rgb.c`) и найдите `g_led_config`:
   - Первая таблица сопоставляет матрицу клавиш с номерами LED, `__` означает «LED нет». На клавиатурах Keychron номера растут слева направо и сверху вниз, так что порядок это просто клавиши в том порядке, в каком вы читаете их на клавиатуре.
   - Вторая таблица даёт физическое положение каждого LED `{x, y}`, по ней удобно проверить порядок.
   - Впишите в `keys` по одному имени на номер. Имена ваши (любой текст без пробелов, регистр не важен, каждое имя один раз). Для LED, который не клавиша, например подсветки по периметру, пишите `_`.
5. **Поправьте `[groups]`, `[common]` и `[layouts.*]`**, чтобы в них были только имена из вашего списка. При запуске или перезагрузке конфига ошибка назовёт нужную клавишу.
6. **Запустите программу** и посмотрите лог. Строки `device 3434:xxxx, N LEDs` и затем `keyboard connected` значат, что всё работает. Если число LED не совпало с тем, что сообщает клавиатура, в логе будет `keyboard reports N LEDs, config.toml lists M`.

Список клавиш K5 Max в [config.toml](config.toml) служит готовым примером. `rgb.c` для K5 Max ANSI лежит в `keyboards/keychron/k5_max/ansi/rgb/rgb.c`.

### Модели, которые могут подойти

USB ID взяты из файлов `info.json` в исходниках Keychron, vendor ID `0x3434`. На железе я их не проверял (только `0x0A50`), так что сверяйтесь с `--list`. Число LED у каждой модели своё, возьмите его из `--probe`.

| Модель | ANSI | ISO | JIS |
|---|---|---|---|
| K1 Max | `0x0A10` | `0x0A11` | `0x0A12` |
| K2 Max | `0x0A20` | `0x0A21` | `0x0A22` |
| K3 Max | `0x0A30` | `0x0A31` | `0x0A32` |
| **K5 Max** (по умолчанию) | `0x0A50` | `0x0A51` | – |
| K7 Max | `0x0A70` | `0x0A71` | `0x0A72` |
| K8 Max | `0x0A80` | `0x0A81` | `0x0A82` |
| K10 Max | `0x0AA0` | `0x0AA1` | – |
| K11 Max (энкодер) | `0x0AB3` | `0x0AB4` | `0x0AB5` |
| K13 Max | `0x0AD0` | `0x0AD1` | – |
| K15 Max (энкодер) | `0x0AF0` | `0x0AF1` | – |
| K17 Max (энкодер) | `0x0A00` | `0x0A01` | `0x0A02` |

Сборки SignalRGB для большинства из них лежат в папке `2025q3` репозитория SRGBmods/QMK-Binaries. Другие серии Keychron (Q Max и прочие) и QMK-клавиатуры других производителей с прошивкой SignalRGB подключаются так же, отличаются только числа. Если у вас получилось, pull request с вашей секцией `[device]` приветствуется.

Протокол ограничивает клавиатуру 255 LED и 32-байтовыми raw HID-пакетами, это стандарт QMK по умолчанию.

## Разработка

```powershell
cargo test
```

Тесты проверяют логику соединения на поддельной клавиатуре (устаревший хэндл после гибернации, молчащее устройство, пробуждение, повторные heartbeat, неверное число LED), разбор конфига и сравнивают получаемые кадры с эталонами из `testdata/`.
